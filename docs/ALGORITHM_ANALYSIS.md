# Анализ алгоритма визуализации диаграммы Венна в проекте Godot

## Общий обзор

Проект реализует **сеточную визуализацию пересечений множеств** (Grid-based Venn Diagram), где элементы данных размещаются в цветных ячейках на двумерной сетке. Это альтернативный подход к классической диаграмме Венна с кругами, который позволяет показать точное количество элементов в каждой области.

---

## Архитектура системы

### Основные компоненты

1. **Main.gd** - главный контроллер
   - Загрузка данных из CSV/Excel
   - Фильтрация данных по параметрам
   - Битовая маркировка элементов
   - Сортировка в области пересечений

2. **Grid.gd** - визуализация
   - Расчет размеров сетки
   - Определение областей для каждой ячейки
   - Отрисовка цветных ячеек
   - Размещение элементов

3. **Cell.gd** - отдельная ячейка
   - Отображение элемента (иконка + текст)
   - Обработка кликов и контекстного меню

## Алгоритм работы: 5 этапов

### Этап 1: Битовая маркировка (Bitmask Assignment)

**Файл:** `Main.gd`, функция `calculate()`

**Принцип:**
Каждый элемент данных проверяется на соответствие трём параметрам фильтрации. Результат записывается в виде 3-битного числа (от 0 до 7):

```
Параметр 1: бит 0 (значение 1)
Параметр 2: бит 1 (значение 2)  
Параметр 3: бит 2 (значение 4)
```

**Битовые маски:**
- `001` (1) = только параметр 1
- `010` (2) = только параметр 2
- `011` (3) = параметры 1+2
- `100` (4) = только параметр 3
- `101` (5) = параметры 1+3
- `110` (6) = параметры 2+3
- `111` (7) = все три параметра

**Код:**
```gdscript
func get_mask(param_tab, param, row_count):
    var checkbox = ...  # Режим фильтра: текст или числовой диапазон
    var textValue = ... # Значение поиска
    var mask = 0 << param
    var index = ...     # Индекс колонки для проверки
    var value = self.data[row_count][index]
    
    if checkbox == true:
        # Числовой диапазон
        if int(value) >= int(textValue) and int(value) <= int(textValue2):
            mask = 1 << param
    else:
        # Текстовый поиск (без учета регистра)
        if str(value).findn(textValue, 0) != -1:
            mask = 1 << param
    
    return mask

# Для каждого файла вычисляется битовая маска XOR всех параметров
for param in param_tab.get_child_count() - 1:
    bit ^= get_mask(param_tab, param, row_count)
```

**Результат:** каждый элемент получает свойство `bit` со значением от 0 до 7.

### Этап 2: Сортировка в области (Area Sorting)

**Файл:** `Main.gd`, функция `create_sorted()`

**Принцип:**
На основе битовой маски элементы распределяются по 7 областям диаграммы Венна:

```gdscript
match file["bit"]:
    1: check_subgroups(1, file, param_tab)  # data1
    2: check_subgroups(2, file, param_tab)  # data2
    3: sorted["data12"].append(file)         # пересечение 1+2
    4: check_subgroups(3, file, param_tab)  # data3
    5: sorted["data13"].append(file)         # пересечение 1+3
    6: sorted["data23"].append(file)         # пересечение 2+3
    7: sorted["data123"].append(file)        # пересечение всех трех
```

**Структура данных:**
```gdscript
sorted = {
    "data1": [],      # Только параметр 1
    "data2": [],      # Только параметр 2
    "data3": [],      # Только параметр 3
    "data12": [],     # Пересечение 1 и 2
    "data13": [],     # Пересечение 1 и 3
    "data23": [],     # Пересечение 2 и 3
    "data123": []     # Пересечение всех
}
```

**Подобласти:**
Для основных областей (data1, data2, data3) может быть дополнительная детализация по подпараметрам (a, b, c, d):

```gdscript
subsorted = {
    "data1": {"a": [], "b": [], "c": [], "d": []},
    "data2": {"a": [], "b": [], "c": [], "d": []},
    "data3": {"a": [], "b": [], "c": [], "d": []}
}
```

### Этап 3: Балансировка (Group Shuffling)

**Файл:** `Main.gd`, функция `shuffle_groups()`

**Принцип:**
Области меняются местами так, чтобы самая большая область всегда была первой (`data1`). Это улучшает визуальное восприятие диаграммы.

**Алгоритм пузырьковой сортировки:**
```gdscript
func shuffle_groups():

    swap_groups("data1", "data2", "data13", "data23")  # Повторная проверка 1 и 2

        # Обмен sorted и subsorted массивов
        ...
```

**Зачем нужно:**
- Самая большая область занимает левую часть диаграммы
- Улучшается читаемость
- Оптимизируется расположение пересечений

### Этап 4: Расчет размеров сетки (Grid Size Calculation)

**Файл:** `Grid.gd`, функция `calculate_sizes()`

**Принцип:**
На основе количества элементов в каждой области вычисляются размеры сетки. Используется **эвристический алгоритм** для создания компактной и читаемой визуализации.

**Шаги алгоритма:**

#### Шаг 4.1: Подсчет элементов в подобластях
```gdscript
n1a = subsorted["data1"]["a"].size()
n1b = subsorted["data1"]["b"].size()
n1c = subsorted["data1"]["c"].size()
n2a = subsorted["data2"]["a"].size()
n2b = subsorted["data2"]["b"].size()
n2c = subsorted["data2"]["c"].size()
n3a = subsorted["data3"]["a"].size()
n3b = subsorted["data3"]["b"].size()
n3c = subsorted["data3"]["c"].size()
```

#### Шаг 4.2: Расчет размеров пересечений
```gdscript
n123 = sorted["data123"].size()           # Центральное пересечение
n12 = sorted["data12"].size() + n123      # Включая центр
n13 = sorted["data13"].size() + n123      
n23 = sorted["data23"].size() + n123
```

#### Шаг 4.3: Расчет общих размеров областей
```gdscript
# Суммарное количество элементов в каждой области
n1 = sorted["data1"].size() + n12 + n13 + n1a + n1b + n1c
n2 = sorted["data2"].size() + n12 + n23 + n2a + n2b + n2c
n3 = sorted["data3"].size() + n13 + n23 + n3a + n3b + n3c
```

#### Шаг 4.4: Вычисление высоты и ширины по формуле sqrt
```gdscript
# Приближенная квадратная форма для каждой области
# Коэффициент 1.3 делает область более горизонтальной
h1 = ceil(sqrt(n1) / 1.3)
h2 = ceil(sqrt(n2) / 1.3)
l1 = ceil(n1 / h1)
l2 = ceil(n2 / h2)
```

**Формула:** 
```
h = sqrt(n) / 1.3  (высота)
l = n / h          (ширина)
```
где `n` - количество элементов

#### Шаг 4.5: Расчет размеров пересечений
```gdscript
h12 = min(h1, h2)           # Высота пересечения = минимум из двух
l12 = ceil(n12 / h12)       # Ширина пересечения 1+2
l123 = l12                  # Центральное пересечение = ширине l12
h123 = ceil(n123 / l123)    # Высота центра
```

#### Шаг 4.6: Финальные размеры всей сетки
```gdscript
if n123 > 0:
    l = l1 + l2 - l123      # Общая ширина (с учетом наложения)
    h = h1 + h3 - h123      # Общая высота
else:
    l = l1 + l2 - l12
    h = h1 + h3 - h12
```

**Концептуальная схема:**

```
┌─────────────────┬─────────────────┐
│                 │                 │
│     data1       │     data2       │
│                 │                 │
├────────┬────────┼────────┬────────┤
│        │ data12 │ data23 │        │
│ data1  ├────────┼────────┤ data2  │
│        │ data13 │123│ d23│        │
├────────┴────────┴────┴───┴────────┤
│              data3                │
│                                   │
└───────────────────────────────────┘

l1 = ширина области 1 + пересечения
l2 = ширина области 2 + пересечения
l3 = ширина области 3
l12 = ширина пересечения 1+2
l123 = ширина центрального пересечения

h1 = высота области 1
h2 = высота области 2  
h3 = высота области 3 + пересечения
h12 = высота пересечения 1+2
h123 = высота центрального пересечения
```

### Этап 5: Размещение элементов (Cell Placement)

**Файл:** `Grid.gd`, функция `drawPrefab(x, y, prefab)`

**Принцип:**
Для каждой ячейки сетки (координаты x, y) определяется, к какой области она относится, на основе заранее рассчитанных размеров.

**Алгоритм определения области:**

Функция содержит **сложную систему условий** (более 200 строк if-else), которая определяет область по координатам:

```gdscript
func drawPrefab(x, y, prefab):
    var area = ""
    var subarea = ""
    
    # Две ветки: с центральным пересечением (n123 > 0) и без
    if n123 > 0:
        # Сложная логика для 7 областей + подобласти
        if y < h3 - h123:
            # Зона data3 (верхняя часть)
            if x < l1 - l13 - l123 or x >= l1 + l23:
                area = ""
            else:
                area = "data3"
                # Определение подобласти a/b
                if n3a > 0 and x <= l1 - l13 - l123 + ceil(l3/2) - 1:
                    subarea = "a"
                elif n3b > 0 and x > l1 - l13 - l123 + ceil(l3/2):
                    subarea = "b"
        elif y < h3:
            # Центральная горизонтальная полоса с пересечениями
            if x < l1 - l13 - l123:
                area = "data1"
            elif x >= l1 - l13 - l123 and x < l1 - l123:
                area = "data13"
            elif x >= l1 - l123 and x < l1:
                area = "data123"  # Центр!
            elif x >= l1 and x < l1 + l23:
                area = "data23"
            else:
                area = "data2"
        # ... и так далее для остальных зон
    else:
        # Упрощенная логика для случая без центрального пересечения
        ...
    
    # Получение цвета для области
    var color_name = "cell_"
    if area != "":
        color_name += area.erase(0, 4)  # "data1" -> "1"
        if subarea != "":
            color_name += subarea         # "1" -> "1a"
        color = palette[palette_ind][color_name]
    
    # Извлечение элемента из соответствующей области
    if area != "":
        if subarea != "":
            files = self.subsorted[area][subarea]
        else:
            files = self.sorted[area]
        
        var file = files.pop_back()  # Берем элемент из конца
        prefab.set_data(file, area, subarea, color, main)
    
    return prefab
```

**Визуализация логики определения областей:**

```
y-координата определяет горизонтальные полосы:

y < (h3 - h123)         → Верхняя часть data3
y < h3                  → Полоса с пересечениями (data1, data13, data123, data23, data2)
y < (h2 + h3 - h123)    → Полоса data1/data12/data2
y >= ...                → Нижняя часть data1

x-координата определяет вертикальные зоны:

x < (l1 - l13 - l123)   → Левая часть data1
x < (l1 - l123)         → Зона data13
x < l1                  → Зона data123 или data12
x < (l1 + l23)          → Зона data23
x >= ...                → Правая часть data2
```

**Ключевая особенность:** элементы извлекаются из массивов `pop_back()`, что означает обратный порядок заполнения (LIFO - Last In, First Out).

## Математическая модель

### Формула размеров области

Для области с `n` элементами:

```
aspect_ratio = 1.3 (горизонтальная ориентация)
h = ⌈√n / aspect_ratio⌉
l = ⌈n / h⌉
```

**Пример:**
- n = 100 элементов
- h = ⌈√100 / 1.3⌉ = ⌈10 / 1.3⌉ = ⌈7.69⌉ = 8
- l = ⌈100 / 8⌉ = 13
- Сетка: 13×8 = 104 ячеек (4 пустые)

### Расчет пересечений

Пересечения размещаются на границах областей:

```
h_пересечения = min(h_области1, h_области2)
l_пересечения = ⌈n_пересечения / h_пересечения⌉
```

### Общие размеры сетки

```
L = l1 + l2 - l_наложения
H = h1 + h3 - h_наложения

где l_наложения = l123 или l12 (в зависимости от наличия центра)
```

## Ключевые принципы

### 1. Битовая логика (XOR-based filtering)
Использование побитовых операций для эффективного определения принадлежности элемента к множествам.

### 2. Двухуровневая сортировка
- **Первый уровень:** основные области (data1, data2, data3, пересечения)
- **Второй уровень:** подобласти (a, b, c, d) внутри основных

### 3. Эвристический расчет размеров
Использование формулы `sqrt(n) / aspect_ratio` для создания компактных прямоугольных областей.

### 4. Координатная логика размещения
Сложная система if-else условий для определения области по координатам (x, y).

### 5. LIFO-порядок заполнения
Элементы извлекаются из конца массива (`pop_back()`), что может быть важно для порядка отображения.

### 6. Кэширование для UI
Дублирование данных в `sorted_cache` и `subsorted_cache` для быстрого доступа при отображении контекстных меню.

### 7. Динамическая адаптация
Алгоритм работает с любым количеством элементов и автоматически подбирает размеры сетки.

## Сложность алгоритма

### Временная сложность:

- **Фильтрация:** O(n × m), где n - количество строк, m - количество параметров
- **Сортировка:** O(n) - однопроходная
- **Расчет размеров:** O(1) - фиксированное количество операций
- **Размещение:** O(h × l), где h и l - размеры сетки
- **Общая:** O(n × m + h × l) ≈ O(n) при небольшом m

### Пространственная сложность:

- **Исходные данные:** O(n × c), где c - количество колонок
- **Отсортированные массивы:** O(n)
- **Кэш:** O(n)
- **Сетка:** O(h × l) ≈ O(n)
- **Общая:** O(n × c)

## Ограничения и особенности

### Ограничения:
1. **Максимум 3 параметра** - битовая маска рассчитана на 3 бита (0-7)
2. **Максимум 4 подобласти** - подпараметры a, b, c, d
3. **Только пересечения множеств** - не поддерживается инверсия (элементы НЕ в множестве)

### Особенности:
1. **Нелинейное размещение** - сложная логика определения областей
2. **Визуальная оптимизация** - балансировка размеров для удобства восприятия
3. **Цветовое кодирование** - интуитивное понимание пересечений
4. **Масштабируемость** - работает с сетками любого размера

## Возможные улучшения

### 1. Упрощение логики размещения
Текущая функция `drawPrefab()` содержит >200 строк вложенных условий. Можно разбить на подфункции:

### 2. Поддержка N параметров
Вместо жестко закодированных 3 параметров использовать динамическое количество:

var n_params = params.size()

### 3. Оптимизация расчета размеров
