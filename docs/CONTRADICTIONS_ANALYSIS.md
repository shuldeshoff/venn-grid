## ❌ КРИТИЧЕСКИЕ ПРОТИВОРЕЧИЯ

### 1. Формат входных данных и архитектура

**TZ.md (раздел 4.2):**
```javascript

```

**ALGORITHM_ANALYSIS.md (Pipeline обработки):**
```
[CSV Файл] → [Загрузка] → [Фильтрация по параметрам] → 
[Битовая маркировка] → [Сортировка в области]
```

**Проблема:**
- **ТЗ:** Библиотека получает **готовые отфильтрованные множества** (items уже разделены по sets)
- **Алгоритм Godot:** Начинает с **сырых данных CSV** и сама делает фильтрацию и распределение по областям

**Вывод:** ТЗ **упрощает** задачу - фильтрацию делает Django, библиотека только визуализирует. Алгоритм Godot делает **всё сам**.

### 2. Механизм битовой маркировки

**TZ.md (раздел 8.1):**
```javascript
function calculateBitmasks(sets) {
    // Должен рассчитывать битовые маски из готовых множеств
    // Элемент принадлежит set1, set2 или обоим?
}
```

**ALGORITHM_ANALYSIS.md (Этап 1):**
```gdscript
# Битовая маска рассчитывается через фильтрацию
func get_mask(param_tab, param, row_count):
    # Проверяет соответствие параметрам фильтрации
    if str(value).findn(textValue, 0) != -1:
        mask = 1 << param
```

**Проблема:**
- **ТЗ:** Битовые маски должны определяться **пересечением готовых множеств** (элемент есть в set1? в set2? в обоих?)
- **Алгоритм Godot:** Битовые маски определяются **результатом фильтрации** (элемент подходит под параметр 1? параметр 2? оба?)

**Это РАЗНЫЕ подходы к одной задаче!**

**Правильный подход для ТЗ:**
```javascript
function calculateBitmasks(sets) {
    // Для каждого уникального элемента определяем в каких множествах он есть
    const allItems = new Map();
    
    sets.forEach((set, index) => {
        set.items.forEach(item => {
            if (!allItems.has(item.id)) {
                allItems.set(item.id, {item: item, bitmask: 0});
            }
            allItems.get(item.id).bitmask |= (1 << index);
        });
    });
    
    return allItems;
}
```
